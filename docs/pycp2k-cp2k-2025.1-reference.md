# PyCP2K with CP2K 2025.1 Reference

## TL;DR

Yes — pycp2k can drive CP2K 2025.1, but you have to install pycp2k in "manual" mode so it regenerates its Python class tree from the 2025.1 XML description. Because the package itself hasn't had a formal release since 2019, the safest, "it-just-works" combination today is usually:

| What you need | Recommended, low-friction choice |
|---------------|-----------------------------------|
| Python wrapper | pycp2k cloned from GitHub and installed with python setup_manual.py |
| CP2K engine | CP2K 2024.3 (stable maintenance) |

If you want the very latest features in 2025.1, go ahead—just regenerate the XML and run the test suite before production jobs.

---

## Why it works

- **Version-agnostic design** – pycp2k builds its API by parsing the XML file generated by any CP2K executable (cp2k --xml). That means new keywords and sections present in CP2K 2025.1 are automatically captured when you re-run the manual installer. The authors even state that the default 5.1 build "should work with most other versions," and advise a manual install for newer releases.
- **CP2K 2025.1 availability** – The CP2K project released 2025.1 on 1 Jan 2025, so the XML generator is already in the public binary/source tree.

## Caveats with 2025.1 + pycp2k

1. **No PyPI update** – The latest PyPI wheel (pycp2k 0.2.2) dates back to Feb 2019 and is hard-wired to CP2K 5.1. Installing that wheel and pointing it at 2025.1 will miss new sections/keywords.
2. **Testing overhead** – 2025.1 adds Bethe–Salpeter time propagation, RPA-Σ functionals, new Z-matrix options, etc. None of those have community-tested examples in pycp2k yet. You'll need to run a small integration test (e.g., a single-point Quickstep job) to confirm the regenerated classes behave.
3. **Occasional renames** – If a keyword disappeared or was renamed in 2025.1, any of your old Python scripts will break at runtime. The error messages are usually explicit ("Unknown keyword …"), so they're easy to fix, but it's something to watch for when upgrading.

## Practical installation recipe for CP2K 2025.1

```bash
# 1. Clone the wrapper
git clone https://github.com/SINGROUP/pycp2k.git
cd pycp2k

# 2. Make sure cp2k 2025.1 is in your PATH
which cp2k            # should point to the 2025.1 binary

# 3. Generate the XML and install
python setup_manual.py install --user   # follow prompts
```

During the prompts:
- When asked "Create XML via cp2k –xml?" say yes.
- Provide the full path to the 2025.1 executable if it isn't the default cp2k.popt.
- Supply your preferred mpirun command (or leave blank for serial).

After installation, try:

```python
from pycp2k import CP2K
c = CP2K()
print(c.CP2K_INPUT.GLOBAL.keys())  # should print 2025.1-specific keywords
```

If that runs without AttributeError, you're good.

## Recommended "stable" combo

If you'd rather not spend time validating a fresh release, stick with CP2K 2024.3 (or 2024.2) and install pycp2k manually in the same way. Those versions have been in the field longer and most community examples target them. The upgrade path to 2025.1 later is straightforward once pycp2k users start submitting patches.
